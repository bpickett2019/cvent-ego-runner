capacity.total=-1 and admission-item scope, including fixed-price, percentage and amount
methods. Three new synthetic mock-transport cases in item-discounts.test.mjs verify
inactive creation → one admission link → finalization → independent mock readback,
then unchanged/no-write repetition. All nine item-discount tests pass. The adapter
does not itself interpret workbook blanks; the agent supplies approved decisions.
This is not live tenant validation or a claim that the selected event's discounts exist.

Missing/duplicate answer codes, duplicate answer labels, show-name placeholders,
source-date/path/approval conflicts, palette slots and concurrent-editor warnings
already have decisions in the skill. Renumbered/reordered sheets are not tool gaps.
Do not add more agents, new policy tables, a broad deletion engine or alternate APIs
to work around these issues. Continue independent safe work around ordinary blockers.

## Source decisions are not software fixes

A registration-type reference with multiple plausible matches must follow the skill's
unique-match-or-skip rule. An approved source clarification can resolve the identity;
a generic placeholder or an expanded audience cannot. A skipped included fee remains
unfinished and prevents full DONE. Preserve original workbook values and record any
operator-approved correction through the normal versioned input process.

Likewise, a missing asset target is not permission to replace an instructed link with
NULL. Fill-in rules apply in their stated situations, not to unverified resources,
unknown relationships or failed operations. Saved existing configuration may resolve
some apparent gaps, but only after actual readback—not from historical findings.

## Minimal tester discovery brief

Use an authorized tester's assigned event/session, with exact event identity and scope
confirmed. The project owner does not need to provide Cvent credentials. First inspect
without saving; collect only the relevant control labels, whether the setting is
shared/event-local, and a sanitized observation or screenshot without credentials or
attendee data. No other-event inspection, publication, registration preview by the
agent, or registration submission is part of this task.

A human can inspect in their authorized human-owned session. Do not press Return to
Agent, alter ownership or start a paid build solely to grant the coding agent access.
Any agent browser inspection, new session/build or control handoff requires its own
existing authorized app flow and gate. Read-only intent does not bypass ownership.

1. **Footers:** identify each target path's current component and its assignment
   controls. Establish whether changes can be isolated without affecting unnamed paths
   or account templates. Do not save a trial to find out after the fact.
2. **Choice codes:** inspect one relevant question's choice settings and any supported
   event-question editor. Determine whether a true per-choice code field exists.
   Record the surface and readback route; finding Question Code alone is not success.
3. **Event capacity:** locate the total event registration limit, if exposed, and
   distinguish it from item/type limits. Record how its saved value is checked.
4. **Assets and relationships:** identify the approved existing policy link/document,
   and confirm needed sub-question/Other/visibility controls. Check scope of requested
   planner/group/processing settings before authoring them.

After separately approved scoped configuration, verify saved fields/relationships by
reopening the editor or using supported reads. Record changed versus already-correct
state accurately. A completed save signal alone is not persistence. If an outcome is
uncertain, stop and retain evidence; never repeat Save or clear markers. No test
registration or publishing is needed to verify saved configuration.
