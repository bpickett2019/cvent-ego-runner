## Plan and acceptance gates

1. **Requirement map.** Bind the original workbook/checksum and selected event. Map
   every included requirement to intent, operation, saved proof and dependency.
   Historical run findings are useful planning inputs, not complete workbook coverage
   or current saved evidence. The user subsequently selected an exact local original;
   its checksum and source-derived acceptance map are recorded privately. The old
   historical-results map remains separate. The selected workbook uses an older tab
   and question layout. The user clarified that layout is discovered from names,
   headers and contents, while SKILL.md always controls scope and execution order.
   Mere reordering/renumbering is not a blocker or a separate approval gate.
2. **Instruction package.** Keep the exact skill; align technical references and
   installation inventory together. Resolve links, verify policy preservation and
   review relevant tests. The current source candidate is not a release approval.
3. **Capability discovery.** Establish supported routes for footer separation, supplied
   answer codes, event capacity, asset targets and any necessary identity/replacement
   work. Prefer existing operations; implement only demonstrated gaps needed by the
   workbook. Known pre-write gaps do not halt independent configuration. They still
   prevent full completion if included requirements remain unsatisfied.
4. **Connected verification.** Cover interpretation, saved readback, relationships,
   reports/UI and controller settlement, plus independent-work continuation and
   safety stops. Synthetic checks are not Cvent acceptance. Reconcile obsolete test
   expectations without disabling valid safety tests or fabricating private fixtures.
5. **Approved rollout and fresh run.** Deployment portion complete with installed,
   preservation and HTTPS checks. A fresh paid build still requires separate approval
   and fresh ownership/event checks. No automatic build or repeat builds. Step 3
   discovery is part of normal authorized staging use, not a separate predeployment
   tester prerequisite.
6. **Closeout.** Compare every included requirement with saved evidence and approved
   policy decisions. Any remaining configuration is INCOMPLETE, not a display fix.
   Stop/uncertainty retains evidence and never authorizes session resumption or replay.
