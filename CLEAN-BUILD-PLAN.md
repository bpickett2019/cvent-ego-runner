# Clean-browser lifecycle

Current contract: [RPC-CONNECTION.md](RPC-CONNECTION.md). Activation state and pending changes: **CURRENT** in [MVP-HANDOFF.md](MVP-HANDOFF.md). Historical PIDs and receipts are not current runtime-state evidence or restart authorization.

1. Upload the RR and bind the selected existing event; preserve immutable originals/version history. No model call yet.
2. Start provisions the job's fresh local Steel browser/profile without copying cookies or disturbing previous/unrelated services.
3. The human logs in. Waiting uses local checks, not Pi polling or paid prompts.
4. Explicit Return verifies authentication, identity, ownership, security attestations, uncertainty and accounting readiness before one fresh native session starts.
5. Pi reads the captured standing SOW and workbook, chooses its own plan and tools (Ego/Steel and supported API operations), and verifies saved Draft results. Existing event-only edits are allowed; existing shared definitions stay unchanged. No mandatory requirements ledger or second agent.
6. Settlement/Stop retains workbooks, profiles, reports and costs. Uncertain writes are never replayed. No automatic next RR or retry from a failed step.

Automatic dollar thresholds were removed in source; lost/unknown metering still stops. The authorized app restart activated that change; see CURRENT in MVP-HANDOFF.md for its receipt. Expired login, ownership/identity loss and other safety stops remain.

The original plan, lifecycle tests and earlier activation receipts are retained byte-for-byte in [the historical archive](docs/history/CLEAN-BUILD-PLAN.md), not as active create-only, checklist or cumulative-dollar-stop instructions. Full live RR completion remains unproven.
